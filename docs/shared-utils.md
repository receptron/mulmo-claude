# Shared Utilities Catalog

> **Before writing a new helper, check this list.** If a similar helper already exists, use it. When you add a new shared helper (a cross-cutting formatter, error normaliser, path joiner, etc.) append a 1-line entry here in the same PR.

Skipping this step is how `truncate()` ended up with 6 implementations, `formatBytes()` with 2 + an inline copy, and the `err instanceof Error ? err.message : String(err)` pattern with ~65 inline copies plus 14 named implementations across 4 behaviours (#2217). The catalog is the prevention mechanism. (Tracking: #1304.)

This catalog only covers **cross-cutting** helpers — formatters, error helpers, network wrappers, path joiners, shared regex. One plugin's parser or one route's validator stays inside that plugin / route; it doesn't belong here.

## Known duplicates — read before "just adding one more"

The catalog's own failure mode is listing **one** member of a family and hiding
the rest, which is how `errorMessage` reached 14 implementations while the entry
above named 2 (#2217). This section names every family that still has more than
one live implementation, so a fix can be applied to all of them instead of the
first one grep happens to find.

**Architecturally forced vs. accidental:** `packages/core` cannot import from
`server/`, and plugins cannot import each other — so *some* second copy is
unavoidable. A plugin with no `@mulmoclaude/core` dependency is only *soft*
forced: adding the dep would resolve it. Everything marked accidental has no
rule requiring it.

| Helper | Copies | Diverged? | Notes |
| --- | --- | --- | --- |
| `errorMessage` | 1 canonical + plugin copies (accounting, markdown, mulmoscript, x, spotify, html) | plugin copies vary; `x-plugin` drops the `fallback` param | Core + host now share `@mulmoclaude/core/utils`. Plugin copies are soft-forced (no core dep). Roughly 65 inline `err instanceof Error ? … : String(err)` sites also remain. |
| `isRecord` | 14 | **YES — 2 let arrays through** | `server/plugins/runtime-loader.ts` and `spotify-plugin/src/normalize.ts` omit `!Array.isArray`, so `isRecord([1,2,3])` narrows an array to `Record<string, unknown>`. The host one is **accidental** — `server/utils/types.ts` exports both `isRecord` and the array-tolerant `isObj`. |
| `fetchWithTimeout` | 4 | **YES — `x-plugin`** | `x-plugin/src/internal.ts` omits the pre-aborted check and the signal bridge, then overwrites a caller-supplied `signal`. Safe only while no X tool passes one. Core's two copies (`collection/registry/server/fetch.ts`, `google/fetch.ts`) are byte-identical and **accidental** — same package. |
| `writeFileAtomic` | 3 | **YES** | `opts.mode` is honoured only by `server/utils/files/atomic.ts`; the core and accounting copies silently ignore it (files land at default umask). They also flip the `uniqueTmp` default, changing concurrent-writer behaviour. |
| `slugify` | 6 | minor | The three plugin copies (chart / html / mulmoscript) differ in truncation order: chart caps *after* stripping leading hyphens, the others *before*. Only affects length for titles starting with punctuation; filenames are throwaway + timestamped. |
| `escapeHtml` | 5 | no | Two spellings (switch-map vs. chained `.replace`), identical output. `@mulmoclaude/core/wiki`'s `render.ts` already is a shareable escaper. |
| `yearMonthUtc` | 3 | no | `server/utils/files/naming.ts` is canonical; chart / html plugins keep private copies. |
| `toUtcIsoDate` | 3 | no | `server/utils/date.ts`, `packages/scheduler/src/date.ts`, `x-plugin/src/internal.ts`. |
| `safeResponseText` | 2 | no | `server/utils/http.ts` and `x-plugin/src/internal.ts`. |
| `asyncHandler` | 2 | no | `server/utils/asyncHandler.ts` and `accounting-plugin/src/server/http.ts`. |
| Time constants | 13+ | no | Values agree everywhere. `server/workspace/wiki-pages/snapshot.ts` re-declares `ONE_DAY_MS` inside `server/` (**accidental** — `server/utils/time.ts` is one import away). The frontend has no catalogued source; `src/composables/useRunElapsed.ts` and `src/utils/agent/formatElapsed.ts` each declare their own. |
| `badRequest` / `notFound` | 2 shapes | n/a | Same names, different contracts: `server/utils/httpError.ts` returns an Express `Response`; `mulmoscript-plugin/src/core/plugin.ts` returns a `MulmoScriptFailure`. A grep for the name finds both — check which you want. |
| `isSafeSlug` | 2 | deliberate | `collection/core/ids.ts` (character-class rule) vs `wiki/slug.ts` (separator / `..` / NUL rule). Both catalogued, each notes the other. **This is the pattern to copy.** |

## Adding a new shared helper

1. **Search first.** Grep this catalog and the relevant directory for an existing helper. Reaching for a generic name (`truncate`, `format`, `parse`) often surfaces a near-match.
2. **If nothing fits, write the helper** in the appropriate location (`server/utils/...` for server, `src/utils/...` for frontend). Co-locate with similar helpers; don't make a new top-level file unless it's a new area.
3. **Add tests** under `test/` mirroring the source path.
4. **Append one line to this catalog** in the same PR, under the right area. The entry shape is `path` — `helper(signature)` — one-line "when to use".
5. **If your helper supersedes scattered call sites,** include the migration in the same PR when it's small (< ~5 sites) or open a follow-up refactor issue for larger sweeps.
6. **Check the duplicates table above.** If the helper you're touching is listed there, fix *every* copy or say in the PR which ones you deliberately left and why — that table exists because fixing only the first grep hit is how these families grew.
